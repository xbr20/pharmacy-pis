## 一、系统功能与真实业务数据

系统按彩色建模架构型落地为 16 个功能模块，页面与建模产物一一对应：

| 模块 | 说明 |
|---|---|
| 登录 / 登出 | HttpOnly Cookie + HMAC 签名会话，未登录访问受保护页面自动跳登录页 |
| 仪表盘 | 药品品种／批次／近效期／紧急／待隔离／今日销售 6 项指标，对应 1.1 愿景度量指标 |
| 近效期预警 | 90／30／7 天三级 + 已过效期分级，替代纸质《效期登记本》（改进点：每天翻货架 → 每天看清单） |
| 近效期处置 | 可交互登记，系统按规则拦截不合规动作（距效期不足 7 天只能下架隔离或报损；处方药剩余 ≤30 天不得促销） |

## 五、本地运行

前置：Node.js ≥ 18（本项目在 Node 22 上验证通过）。

```bash
# 1. 安装依赖
npm install

# 2. 生成 Prisma 客户端 + 建表
npx prisma generate
npx prisma migrate deploy      # 开发期可用：npx prisma migrate dev

# 3. 灌入模拟数据（60 种药品 / 120 个批次 / 55 单销售 / 265 条库存流水 …）
npm run db:seed

# 4. 启动
npm run dev                    # http://localhost:3000
# 或生产模式：npm run build && npm start
```

浏览器打开 http://localhost:3000 ，使用 `admin / admin123` 登录。

**自检脚本**（44 项，当前全部通过）：

```bash
npm test
```

覆盖：数据规模、唯一约束（药品编码／追溯码／会员卡号／库位编码／批号联合唯一）、业务规则（效期三级分级、处置动作合法性、会员日双倍积分）、外键完整性、库存流水前后勾稽、追溯事件链完整性。

### 切换 PostgreSQL

```bash
cp prisma/schema.postgresql.prisma prisma/schema.prisma
# 修改 .env：DATABASE_URL="postgresql://user:password@localhost:5432/pis?schema=public"
npx prisma migrate dev --name init
npm run db:seed
```

也可直接执行 `sql/schema.sql`（PostgreSQL 建表脚本，与 Prisma 模型结构一致）。

│  │  ├─ prescriptions/ sales/           # 处方登记 / 销售单
│  │  └─ stocktakes/ members/ member-purchases/ staff/   # 库存盘点 / 会员 / 会员购药记录 / 店员与排班
│  └─ api/                   # 登录、登出、处置登记等 Route Handlers
├─ components/               # 侧边导航、数据表格、处置表单
├─ lib/                      # prisma 客户端、认证、业务规则、格式化
├─ prisma/
│  ├─ schema.prisma          # 数据模型（SQLite，唯一事实来源）
│  ├─ schema.postgresql.prisma # PostgreSQL 版（由 scripts/sync_pg_schema.js 派生）
│  ├─ migrations/            # 初始化迁移
│  └─ seed.js                # 模拟数据脚本
├─ scripts/check.js          # 44 项自检脚本
├─ scripts/sync_pg_schema.js # 由 SQLite schema 派生 PostgreSQL schema
├─ scripts/start.js          # 生产启动（构建 Client / 初始化数据 / 重建效期状态）
